# 审批（Approval）功能 UI 对接规格

> 本文档自包含，不需要读其他文件即可开始实现。

---

## 1. 背景：审批机制是什么

Mederi 的 AI Agent 在执行工具时，某些危险操作（写文件、编辑文件、打补丁、执行命令）需要用户确认后才能继续。这就是审批机制。

### 1.1 完整流程

```
用户发送消息 "创建一个文件 test.txt"
    ↓
Agent 决定调用 write_file 工具
    ↓
write_file 工具执行前，调 approvalRequester.request(toolName, description, args)
    ↓
core 发出 APPROVAL_REQUESTED 事件，工具协程挂起（等待用户回复）
    ↓
UI 收到事件 → 显示审批对话框（工具名、参数、描述）
    ↓
用户点击"允许"或"拒绝"
    ↓
UI 调 aiCore.resolveApproval(conversationId, approvalId, approved, feedback)
    ↓
core 发出 APPROVAL_RESOLVED 事件，工具协程恢复
    ↓
approved=true → 工具继续执行
approved=false → 工具返回"用户拒绝"，Agent 放弃此操作
```

### 1.2 核心已实现的部分

**`ApprovalRequester` 类**（`core/src/main/kotlin/xyz/mederi/approval/ApprovalRequester.kt`）：

```kotlin
class ApprovalRequester(
    private val sessionId: String,
    private val eventBus: MutableSharedFlow<MederiEvent>
) {
    // 工具调用此方法，挂起等待用户回复
    suspend fun request(toolName: String, description: String, args: String): ApprovalResult

    // 用户回复后调此方法，恢复挂起的工具协程
    suspend fun resolve(approvalId: String, approved: Boolean, feedback: String?): Boolean

    // turn 结束时清理所有未完成的审批
    fun cancelAll()
}
```

`request()` 做的事：
1. 生成 `approvalId`（格式 `appr_xxxxxxxx`）
2. 创建 `CompletableDeferred<ApprovalResult>` 存入 `pending` map
3. 发出 `APPROVAL_REQUESTED` 事件到 eventBus
4. `return deferred.await()` — 挂起，直到 `resolve()` 被调用

`resolve()` 做的事：
1. 从 `pending` map 取出对应的 `CompletableDeferred`
2. `deferred.complete(ApprovalResult(approved, feedback))` — 恢复工具协程
3. 发出 `APPROVAL_RESOLVED` 事件

### 1.3 事件 payload 格式

**APPROVAL_REQUESTED** 事件的 `payload`（`Map<String, String>`）：

| key | 值 | 示例 |
|---|---|---|
| `approvalId` | 审批 ID | `"appr_a1b2c3d4"` |
| `tool` | 工具名 | `"write_file"` |
| `description` | 描述 | `"写入文件 /tmp/test.txt"` |
| `args` | 参数 JSON | `{"path":"/tmp/test.txt","content":"hello"}` |

**APPROVAL_RESOLVED** 事件的 `payload`：

| key | 值 | 示例 |
|---|---|---|
| `approvalId` | 审批 ID | `"appr_a1b2c3d4"` |
| `approved` | 是否批准 | `"true"` 或 `"false"` |
| `feedback` | 用户反馈 | `"looks good"` 或 `""` |

## 2. 问题：UI 层两处断裂

core 的审批机制已完整实现，但 UI 层有两处没接上：

### 断裂点 1：事件聚合器忽略审批事件

**文件**：`mederi/ui/shared/src/jvmMain/kotlin/xyz/mederi/core/bridge/MederiEventAggregator.kt`
**位置**：第 89-90 行

```kotlin
EventType.TOOL_CALLED, EventType.TOOL_RESULT,
EventType.APPROVAL_REQUESTED, EventType.APPROVAL_RESOLVED -> snapshot
```

这四个事件被合并到一个 `when` 分支，直接返回 `snapshot` 不做任何处理。

**后果**：`ConversationSnapshot.pendingPermissions` 永远是空列表，UI 永远不知道有审批在等待。

### 断裂点 2：ViewModel 回复方法是空壳

**文件**：`mederi/ui/shared/src/commonMain/kotlin/xyz/mederi/core/ui/WorkspaceViewModel.kt`
**位置**：第 124-125 行

```kotlin
fun replyPermission(requestId: String, decision: PermissionDecision) {
}
```

方法体为空，不调 `aiCore.resolveApproval()`。

**后果**：即使用户点击了审批按钮，也不会调 core 的 `resolveApproval`，工具会一直挂死。

## 4. 实现需求

### 4.1 改动 1：MederiEventAggregator 补全审批事件处理

**文件**：`mederi/ui/shared/src/jvmMain/kotlin/xyz/mederi/core/bridge/MederiEventAggregator.kt`

**当前代码**（第 89-90 行）：

```kotlin
EventType.TOOL_CALLED, EventType.TOOL_RESULT,
EventType.APPROVAL_REQUESTED, EventType.APPROVAL_RESOLVED -> snapshot
```

**改为**：

```kotlin
EventType.TOOL_CALLED, EventType.TOOL_RESULT -> snapshot

EventType.APPROVAL_REQUESTED -> {
    val request = PermissionRequest(
        id = event.payload["approvalId"] ?: "",
        conversationId = conversationId,
        toolName = event.payload["tool"] ?: "",
        arguments = parseToolArgs(event.payload["args"] ?: ""),
        description = event.payload["description"],
    )
    snapshot.copy(pendingPermissions = snapshot.pendingPermissions + request)
}

EventType.APPROVAL_RESOLVED -> {
    val approvalId = event.payload["approvalId"] ?: ""
    snapshot.copy(
        pendingPermissions = snapshot.pendingPermissions.filterNot { it.id == approvalId }
    )
}
```

**注意**：
- `parseToolArgs()` 方法已存在于同文件（第 191-202 行），用于解析工具参数 JSON。直接复用。
- `PermissionRequest` 需要 import：`import xyz.mederi.core.contract.models.PermissionRequest`。
- `TOOL_CALLED` 和 `TOOL_RESULT` 继续忽略（已有 `MESSAGE_DELTA` type=tool_call 和 `MESSAGE_COMPLETED` 重新拉取覆盖工具状态），但注释说明原因。

### 4.2 改动 2：WorkspaceViewModel 接通回复方法

**文件**：`mederi/ui/shared/src/commonMain/kotlin/xyz/mederi/core/ui/WorkspaceViewModel.kt`

**当前代码**（第 124-125 行）：

```kotlin
fun replyPermission(requestId: String, decision: PermissionDecision) {
}
```

**改为**：

```kotlin
fun replyPermission(requestId: String, decision: PermissionDecision) {
    val convId = conversationId ?: return
    val approved = decision != PermissionDecision.Deny
    val feedback = when (decision) {
        PermissionDecision.AllowOnce -> "allow once"
        PermissionDecision.AllowAlways -> "allow always"
        PermissionDecision.Deny -> "deny"
    }
    viewModelScope.launch {
        appState.aiCore.resolveApproval(convId, requestId, approved, feedback)
    }
}
```

**说明**：
- `PermissionDecision` 有三个值（AllowOnce / AllowAlways / Deny），但 core 的 `resolveApproval` 只接受 `Boolean approved`。
- 映射规则：`Deny → approved=false`，其余 → `approved=true`。
- `feedback` 字符串区分了三种决策，core 可以记录但当前不依赖它做逻辑判断。
- `viewModelScope.launch` 是异步调用，不阻塞 UI 线程。
- `conversationId` 是 ViewModel 的属性（`var conversationId by mutableStateOf<String?>(null)`）。

## 5. 改动后的完整数据流

```
core: write_file 工具调 approvalRequester.request("write_file", "写入文件 test.txt", {"path":"test.txt","content":"hello"})
  ↓
core: 发出 APPROVAL_REQUESTED 事件
  payload = {approvalId: "appr_a1b2c3d4", tool: "write_file", description: "写入文件 test.txt", args: '{"path":"test.txt","content":"hello"}'}
  ↓
MederiEventAggregator: 收到 APPROVAL_REQUESTED
  → parseToolArgs('{"path":"test.txt","content":"hello"}') = {path: "test.txt", content: "hello"}
  → 构建 PermissionRequest(id="appr_a1b2c3d4", toolName="write_file", arguments={...}, description="写入文件 test.txt")
  → snapshot.copy(pendingPermissions = [..., request])
  → emit(snapshot)
  ↓
WorkspaceViewModel: snapshot 更新
  → pendingPermissions 非空
  → UI 渲染审批对话框
  ↓
用户点击"允许"
  ↓
WorkspaceViewModel.replyPermission("appr_a1b2c3d4", PermissionDecision.AllowOnce)
  → approved = true, feedback = "allow once"
  → viewModelScope.launch { appState.aiCore.resolveApproval(convId, "appr_a1b2c3d4", true, "allow once") }
  ↓
MederiAiCore.resolveApproval(convId, "appr_a1b2c3d4", true, "allow once")
  → mederi.sessions.resolveApproval(convId, "appr_a1b2c3d4", true, "allow once")
  ↓
SessionManager.resolveApproval → ApprovalRequester.resolve("appr_a1b2c3d4", true, "allow once")
  → deferred.complete(ApprovalResult(approved=true, feedback="allow once"))
  → 工具协程恢复，write_file 继续执行
  → 发出 APPROVAL_RESOLVED 事件
  ↓
MederiEventAggregator: 收到 APPROVAL_RESOLVED
  → snapshot.copy(pendingPermissions = pendingPermissions.filterNot { it.id == "appr_a1b2c3d4" })
  → emit(snapshot)
  ↓
WorkspaceViewModel: snapshot 更新
  → pendingPermissions 为空
  → UI 隐藏审批对话框
```

## 6. 测试标准

### 6.1 测试原则

1. **禁止掩耳盗铃**：不能用 mock 的 AiCore 测事件聚合，必须用真实的 `Mederi` 实例跑全链路。
2. **必须有数据断言**：每个断言必须检查具体字段值，不能只检查"不报错"或"返回了对象"。
3. **审批流必须端到端验证**：从 sendMessage 触发审批 → UI 收到审批 → resolveApproval → 工具继续执行，每一步都要有断言。

### 6.2 测试用例

#### 测试 1：APPROVAL_REQUESTED 填充 pendingPermissions

**目标**：验证事件聚合器收到 APPROVAL_REQUESTED 事件后，`ConversationSnapshot.pendingPermissions` 被正确填充。

**方法**：用 `Mederi` InMemory 实例，配置 write_file 需审批，发消息触发写文件，collect `observe()` 的 flow，断言快照内容。

**前置条件**：
- 创建 InMemory `Mederi` 实例（`Mederi.create { }`）
- 创建 Provider（type=OPENAI_CHAT）+ API Key + Model
- 创建 Project（目录随意）
- 创建 Session（AgentMode.EXECUTE，mode 自带 write_file 工具）

**注意**：要触发真实审批，需要 LLM 真正调用 write_file。如果用真实 LLM 太慢/太贵，可以改为直接调 `ApprovalRequester.request()` 发出事件，然后验证聚合器。但必须断言 `pendingPermissions` 的具体内容。

**断言**：

```kotlin
// 收到 APPROVAL_REQUESTED 后的快照
val snapshot = snapshots.last { it.pendingPermissions.isNotEmpty() }
assertEquals(1, snapshot.pendingPermissions.size)
val perm = snapshot.pendingPermissions[0]
assertTrue(perm.id.startsWith("appr_"))
assertEquals("write_file", perm.toolName)
assertTrue(perm.arguments.isNotEmpty())  // 参数非空
assertNotNull(perm.description)         // 描述非空
```

#### 测试 2：APPROVAL_RESOLVED 清除 pendingPermissions

**目标**：验证 resolveApproval 后，`pendingPermissions` 被清除。

**方法**：在测试 1 的基础上，调 `mederi.sessions.resolveApproval(sessionId, approvalId, approved=true, feedback=null)`，继续 collect events，断言快照。

**断言**：

```kotlin
// resolveApproval 后的快照
val resolvedSnapshot = snapshots.last { it.pendingPermissions.isEmpty() }
assertTrue(resolvedSnapshot.pendingPermissions.isEmpty())
```

#### 测试 3：replyPermission 调用 resolveApproval

**目标**：验证 ViewModel.replyPermission 正确调用 AiCore.resolveApproval。

**方法**：可以 mock `AiCore` 接口（因为被测的是 ViewModel 如何调 AiCore，不是 AiCore 本身）。但必须验证传入的参数。

```kotlin
// 用 mock AiCore 验证参数
val mockAiCore = object : AiCore { /* 只实现 resolveApproval，记录参数 */ }
val appState = AppState(aiCore = mockAiCore, ...)
val vm = WorkspaceViewModel(appState)
vm.replyPermission("appr_123", PermissionDecision.AllowOnce)

// 断言
assertEquals("appr_123", capturedApprovalId)
assertEquals(true, capturedApproved)
assertEquals("allow once", capturedFeedback)

// 测试 Deny
vm.replyPermission("appr_456", PermissionDecision.Deny)
assertEquals(false, capturedApproved)
assertEquals("deny", capturedFeedback)
```

#### 测试 4：拒绝审批后工具不执行

**目标**：验证 approved=false 时工具不执行操作（如文件没被创建）。

**方法**：真实 Mederi 实例，触发 write_file 审批，调 resolveApproval(approved=false)，断言文件不存在。

```kotlin
val result = mederi.sessions.resolveApproval(sessionId, approvalId, approved = false, feedback = "deny")
assertTrue(result)

// 等待 turn 结束
// 断言文件不存在
assertFalse(File("/tmp/test_approval_deny.txt").exists())
```
