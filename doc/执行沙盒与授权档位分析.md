# Mederi 执行沙盒与授权档位：现状、缺口、做法

对标对象是 Codex 的日常档，不是 Claude Code 的域名代理，也不是 Cursor 的命令允许列表。日常档由两层组成：操作系统强制的边界，以及越界时才弹出的一次同意。Mederi 今天只有边界的文件系统半边，而且只在 macOS 和 Linux。授权档位不存在。

本文只分析产品运行时。`Agents.md` 是开发 Mederi 的仓库规则，不是这套沙盒的产品规格。文中提到要改它，是因为里面有几句在描述产品现状，改完产品后那些句子会变成假话。

已经定下来的产品形状：

- 三档：**严格**、**自动**、**全开**。默认自动。
- 自动档：工作区可写，读全盘，网络默认关，`.git` 只读。框内直接做。写到外面、上网、写 `.git`、脱掉沙盒，才问这一次。
- 严格档：沙盒仍开。每次改文件、每条命令都问。同意之后这条仍在沙盒里跑。
- 全开：不套沙盒，不问。
- Windows 两个后端：有 MXC 用 MXC；没有则用提权安装一次的旧沙盒（专用用户 + 限制令牌 + 防火墙）。两个都没有时，严格和自动拒绝命令，不裸跑。
- 计划批准和 `ask_user` 不动。`AgentMode` 仍只决定谁批计划。

## 1. 现在的代码分成四层

### 1.1 文件工具：全平台同一条 Kotlin 判断

`FileSystemTools.resolveForRead` 不看目录，相对路径才落到项目目录里找。`resolveForWrite` 只接受 `allowedDirectories`（会话挂上的项目目录）。设置页白名单不参与这次判断。拒绝文案却写着「把目录加进项目或沙盒白名单」，和代码不符。

`OfficeTools.resolveForWrite` 是另一份拷贝，同样只认项目目录。

`PatchFileTransaction` 不一样：可写根 = 项目目录 + `SandboxConfig.extraWritablePaths`。它会拒绝符号链接逃逸和 canonical 重复目标。所以今天出现三套写规则：

| 入口 | 可写范围 |
|---|---|
| `write_file` / `edit_file` | 仅项目目录 |
| `office_write` | 仅项目目录 |
| `apply_patch` | 项目目录 + 设置页额外路径 |
| `bash` | 项目目录 + 额外路径 + 临时目录 + 家目录构建缓存 |

目标是四者同一份根，再加同一份「永远不可写」列表。

写之前还有 `FileWriteRegistry`：同一 canonical 路径已被别的工具占用就直接返回错误，不排队。bash 和 MCP 是外部进程，注册表管不到。这层保留，和 Codex 无关。

### 1.2 命令：`ShellTools.runCommand` → `CommandSandbox.wrap`

每条命令（含后台命令、`web_search`、`web_fetch`、子任务验证命令）都走 `runCommand`。包装失败时 Linux 返回 `[sandbox] ...` 且 exitCode `-1`，进程不启动。Windows 包装总是成功，只在输出前加警告。

启动后立刻 `ProcessRegistry.register`。posix 上直接子进程是进程组长（macOS 用 `/usr/bin/perl` 的 `setpgrp(0,0)` 再 exec；Linux 用 `setsid`）。超时和 `stop_process` 在沙盒外按进程组杀。macOS Seatbelt 没有 `process-signal`，沙盒里面的 `kill` 必然 `Operation not permitted`，所以这层不能删。Windows 没有进程组，只有 `taskkill /T`。

`web_search` / `web_fetch` 不是独立 HTTP 栈。`curlGet` 拼一条 `curl -sL ...`，再交给 `runCommand`。网络一关，这两个产品工具会一起被关。这是对标时必须拆开的耦合。

### 1.3 三端命令后端

实现集中在：

- `core/src/commonMain/kotlin/xyz/mederi/tools/sandbox/CommandSandbox.kt`
- `core/src/commonMain/kotlin/xyz/mederi/tools/sandbox/LinuxCommandSandbox.kt`
- `core/src/commonMain/kotlin/xyz/mederi/tools/sandbox/SandboxConfig.kt`（只有 `extraWritablePaths`）

**macOS，已经做了。** `sandbox-exec -f` 加一份 SBPL。`(deny default)` 之后显式放行 exec、fork、mach-lookup、sysctl-read、sysctl-write、ipc、`network*`、`file-read*`，写只给白名单 `subpath`。profile 按内容 hash 缓存在临时目录。`sysctl-write` 必须留：没有它，沙盒里的 `java_home` 找不到 JDK，Gradle 起不来。进程组长包装必须留。

当前写白名单比 Codex 宽。除了项目目录、额外路径、`/tmp`、`$TMPDIR`、`/private/tmp`、`/private/var/folders`，还有这些家目录，存在就放行写：

`~/.gradle`、`~/.m2`、`~/.konan`、`~/Library/Caches`、`~/Library/Java`、`~/.npm`、`~/.bun`、`~/.pnpm-store`、`~/.cargo`、`~/go`、`~/.local`、`~/.cache`。

这些是持久可写洞。代理可以改用户的构建缓存，下次在沙盒外跑构建时吃进去。Codex 默认不放行它们。

网络是 `(allow network*)`，任意出站。`.git` 没有只读例外。没有只读 profile，也没有「这一条命令不套 sandbox-exec」的全开路径。沙盒永远开，这是 `docs/sandbox-plan.md` 的 D1。

**Linux，文件系统半边已经做了，而且失败即停。** `bwrap --unshare-pid --die-with-parent --cap-drop ALL --ro-bind / /`，再把白名单 canonical 路径 `--bind` 成可写。`/dev` 由 bwrap 自己建，不绑 `/dev/std*`。`/proc` 是新的 PID namespace，看不到宿主进程。缺 bwrap、挂载探测失败、白名单盖住 `/`、`/proc`、`/dev`、`/sys`，都抛 `MederiStateException`，命令不跑。每 turn 新建实例，探测各限 10 秒。

还没做的：`--unshare-net`（现状文案写「网络保留」）、`.git` 的 `--ro-bind` 盖层、收掉家目录缓存。白名单目录不存在时会在宿主上 `createDirectories`，这会在沙盒外产生目录，对标后只允许对「用户已同意的可写根」这样做，不能对探测失败的路径乱建。

`PromptGuides.SANDBOX_USAGE` 写的是「没装 bubblewrap 就裸跑加警告」。代码不是这样。提示词在教模型一个不存在的退路。

**Windows，命令沙盒没做。** `status()` 固定 `backend=none, available=false`。`wrap` 变成 `bash.exe -c` 或 `cmd /c`，输出前加「Windows 暂不支持命令沙箱」。文件工具的项目目录判断仍在。这是 Codex 原文里的第二种差选项：不沙盒，也不问。D3 把「不做 Windows 命令沙箱」写成了已拍板决策，这次要推翻。

### 1.4 设置、偏好、已有的两种问人

额外路径存在设备本地 `preferences.json` 的 `sandbox.extraPaths`。`AppState.setSandboxExtraPaths` 写穿 `SandboxConfig`。遥控端没有 `SandboxHooks` 时，设置页只说明「这是宿主配置」，不把手机上的路径假装成服务器白名单。新档位沿用这个宿主语义：命令在哪台机器跑，档位就存在哪台机器。

已有两种问人，都不是执行授权：

| 现有机制 | 问的是什么 | 挂起方式 |
|---|---|---|
| `AgentMode.APPROVAL` + `PlanApprovalRequester` | 整份计划。AUTONOMOUS 则自动批准 | `PLAN_APPROVAL_REQUESTED`，`CompletableDeferred`，`resolvePlanApproval`。重启后请求没了，批准改走一条内部消息开新 turn |
| `ask_user` + `QuestionRequester` | 模型自己决定要用户选题 | `QUESTION_REQUESTED` |

`ShellTools` 文件头写着「无权限弹窗（已拆除）」。D7 写着无逐操作询问。执行同意是第三条通道，卡片、事件、解析接口都新做，不往计划卡上塞。

## 2. 和 Codex 日常档逐项差在哪

| Codex 日常档 | Mederi 今天 | 要做的事 |
|---|---|---|
| 写 = 工作区 + 临时目录 + 用户追加的根 | 命令还默写家目录缓存；文件工具又不认额外路径和临时目录 | 合成一份根，删掉默认家目录缓存 |
| 读全盘 | 已是 | 保持 |
| `.git`（以及代理自己的配置目录）在工作区内仍只读 | `.git` 可写。`~/.mederi` 在工作区外，文件工具本来写不了；项目里的 `.mederi/` 要能写计划 | 只把 `.git/**` 列成永久只读。不锁 `.mederi/` |
| 网络默认关，回环按平台能保留多少留多少 | 三端命令网络全开 | macOS 改 Seatbelt；Linux 加 `--unshare-net`；Windows 用防火墙或 MXC |
| 越界弹一次，同意只覆盖这一次 | 拒绝即结束，或 Windows 上根本不拒绝 | 新的执行同意 |
| 只读 / 工作区可写 / 不沙盒 三档 | 永远开、只有一种封套 | `ExecutionPolicy` |
| Windows：MXC 优先，否则旧沙盒；失败不裸跑 | 裸跑加警告 | helper，未完成前先拒绝 |
| 文件工具和命令同一边界 | 见 1.1 的四套规则 | 一个判断函数 |

Mederi 多出来、对标时保留的：同文件写锁、只杀自己的进程组、macOS 上 `sysctl-write` 和 perl 进程组。Codex 没有对应物，但删掉会弄坏 Gradle 和 `stop_process`。

Mederi 是通用代理。工作区等于这次会话挂上的目录列表，不是「当前 git 根」。会话可以没有 `.git`。保护规则是「如果某个可写根下面有 `.git`，那一层只读」，不是「必须先找到仓库」。

## 3. 三档在每次工具调用上怎么判

动作先分类，再查档位。分类是宿主做的，不相信模型口头说「这是只读命令」。

| 动作 | 严格 | 自动 | 全开 |
|---|---|---|---|
| `read_file` / `list_directory` / `office_read` | 直接做 | 直接做 | 直接做 |
| 工作区内的写（`write_file`、`edit_file`、`apply_patch`、`office_write`），目标不是 `.git` | 问。同意后写 | 直接写 | 直接写 |
| 写到工作区、临时目录、额外路径之外 | 问。同意后只写这一条路径 | 同左 | 直接写 |
| 写 `.git/**` | 问。同意等于这一次「不沙盒」写，而不是把 `.git` 放进默认可写根 | 同左 | 直接写 |
| `bash`，`sandbox=default` | 问。同意后用工作区可写、无网络的封套跑 | 不问，用该封套跑 | 不套沙盒跑 |
| `bash`，`sandbox=network` | 问。同意后工作区可写，这一条有出站 | 同左 | 不套沙盒跑 |
| `bash`，`sandbox=off` | 问。同意后这一条不套沙盒 | 同左 | 不套沙盒跑 |
| 验证命令、后台命令 | 跟 `bash` 同一套 | 同左 | 同左 |

严格档里，用户同意一条普通命令之后，封套是「工作区可写 + 无网络」，不是只读。只读封套只用于还没同意、因此根本不会启动的那些命令。这样「同意改文件」和「同意跑会写文件的测试」用的是同一个写范围。

一次同意的范围：

- 文件：这一个路径，这一次调用。`apply_patch` 里有多个目标时，卡片列出全部目标，同意覆盖这一次补丁里的全部分目标，不覆盖下一次。
- 命令：这一次 `bash` 调用，含它的子进程。后台命令在启动前问，问的是即将交给 `BackgroundTaskManager` 的那一条。
- 不写入设置页白名单，不记住命令文本。

全开是唯一不包后端的档。它和「这一次 `sandbox=off`」的差别是：全开不问，而且之后每条都这样；`sandbox=off` 只放行用户刚点的那条。

## 4. 边界的精确定义

### 4.1 可写根

按这个顺序合并，canonical 之后去重，父目录已经包含子目录时只留父目录：

1. 会话项目目录。
2. 临时目录：`/tmp`（以及 macOS 的 `/private/tmp`、`/private/var/folders`）、`$TMPDIR`、`java.io.tmpdir`。Windows 用 `%TEMP%` 和 JVM 临时目录。
3. `SandboxConfig.extraWritablePaths`。必须是已存在或允许创建的绝对路径。空字符串、相对路径、根目录、`/proc`、`/dev`、`/sys` 及其 Windows 对应物拒绝，沿用 Linux 现在的拒绝规则，提到三端共用。

从默认可写根删除第 1.3 节那串家目录缓存。Gradle、npm、cargo 要写它们时，自动档会因为沙盒拒绝而失败。工具结果告诉模型：可以请用户把该目录加进设置，或用 `sandbox=off` 再跑这一次（会弹窗）。宿主不自动把 `~/.gradle` 写进白名单。

### 4.2 `.git` 只读

对每个可写根，如果 `{root}/.git` 存在，则该树只读。不存在就不创建。

- macOS：profile 里先 `(allow file-write* (subpath root))`，再 `(deny file-write* (subpath root/.git))`。Seatbelt 后写的更具体规则覆盖前面的允许。实现时用一条只碰 `.git/config` 的命令验证拒绝，用一条写项目源文件的命令验证允许。
- Linux：先 `--bind root root`，再 `--ro-bind root/.git root/.git`。bwrap 后挂的覆盖先挂的。`.git` 是文件（submodule 或 worktree 的 gitfile）时 `--ro-bind` 这个文件，不要把它建成目录。
- Windows 旧沙盒：对该路径给沙盒 SID 拒绝写 ACE。MXC：策略里这条路径是 deny，且 deny 优先于祖先的可写。
- 文件工具：目标 canonical 路径落在某个 `.git` 下就视为「写 `.git`」，走第 3 节的问询，不走普通工作区写。

`git status`、`git diff`、`git log` 只读，自动档不弹。`git commit`、`git checkout`、`git rebase` 要写 `.git`，沙盒会拒绝，模型只能升级到 `sandbox=off` 并等用户点头。这是预期，不是漏放行。

### 4.3 网络

默认封套拒绝非回环出站。

- macOS：删掉 `(allow network*)`。放行到 `localhost` / `127.0.0.1` / `::1` 的出站和绑定，这样本机 Gradle daemon 的套接字还在。其余出站拒绝。unix socket 维持现有 ipc 放行，否则不少本机工具会坏。
- Linux：默认前缀加 `--unshare-net`。这个命名空间里的 `127.0.0.1` 不是宿主的 `127.0.0.1`，宿主上的 daemon、数据库、代理都连不到。要连它们的命令使用 `sandbox=network`（弹窗后不加 `--unshare-net`，文件系统挂载仍在）。不在 Linux 上做一套 seccomp 来「只留宿主回环」：那是另一个项目，这次用 Codex 的网络命名空间。
- 这一次要网络：文件系统规则不变，只去掉网络拒绝。macOS 恢复出站允许；Linux 去掉 `--unshare-net`；Windows 用 Online 用户或 MXC 的允许出站策略。
- 不采用环境变量把 `HTTPS_PROXY` 指到 `127.0.0.1:9`。Codex 试过，自己开 socket 的程序直接绕过。

`web_search` / `web_fetch` 改成 JVM 客户端（`java.net.http.HttpClient`，core 是 JVM-only）。超时、字节上限、只允许 `http`/`https`、拒绝单引号注入这些现有约束留在工具里，但不再拼 shell。这样自动档关着命令网络时，调查工具仍能上网。命令里的 `curl` 不能借这条路。

### 4.4 全开和后端不可用

全开：`wrap` 返回原来的 `bash -c` / `cmd /c`，没有 Seatbelt、没有 bwrap、没有 helper。仍登记 `ProcessRegistry`，超时仍能整组杀。

后端不可用（Linux 没 bwrap、Windows 两个后端都没有、MXC 被指定但探测失败）并且档位不是全开：`wrap` 抛错，`runCommand` 返回失败，不启动进程。错误文本写明缺什么，以及用户可以改成全开或去设置页安装。探测失败不缓存成「永远不可用」：现在 Linux 是每 turn 新实例，保持这个，装完 bwrap 下一 turn 就能用。

## 5. 授权通道怎么做

照 `PlanApprovalRequester` 做一条平行链，不扩展计划事件。

### 5.1 核心类型

`ExecutionPolicy`：`STRICT`、`AUTO`、`FULL`。进程内一份 `@Volatile`，和 `SandboxConfig.extraWritablePaths` 一样由设置写穿，下一次工具调用读到新值。已在跑的命令不改封套。

`ExecutionApprovalRequester`，每个 turn 一个，挂在和 `PlanApprovalRequester` 相同的位置（`TurnExecutor` 构造工具的地方）：

- `request(action)` 发 `EXECUTION_APPROVAL_REQUESTED`，然后 `await`。
- payload 用 `@Serializable` DTO，不手拼 JSON：请求 id、会话 id、工具名、摘要（路径列表或完整命令）、申请级别（`workspace`、`outside`、`network`、`unsandboxed`）、cwd。
- `resolve(requestId, allowed)` 只唤醒 id 相符的那一次。
- 同一时刻只挂一个执行请求。新请求到来时旧的以「被取代」完成，工具结果写明被新的请求取代，不执行。
- 用户在卡片还在时发下一句话：按计划批准的现有做法中止旧 turn。执行请求以取消完成，命令不跑。不要学计划批准的「重启后补一条内部消息再跑」。命令没有持久化的「待执行」状态，进程重启等于这次没同意。

### 5.2 契约四处

对齐 `resolvePlanApproval`：

- `AiCore` 增加读档位、写档位、`resolveExecutionApproval(conversationId, requestId, allowed)`。
- `MederiAiCore` 转调 core。
- `ServerAiCore` 走 REST。
- server 增加对应路由。缺一条就会在遥控端 404。

事件走现有 `eventBus` 和 `GET /v1/events`。快照里加 `pendingExecutionApproval`，语义和 `pendingPlanApproval` 相同：只表示此刻有人在等，不把历史命令再显示成待同意。

偏好键 `sandbox.executionPolicy`，缺省 `AUTO`。遥控 UI 没有宿主 hooks 时只展示「策略在运行命令的那台机器上」，不出现一个会改到本地偏好的开关。桌面端有 hooks，设置页可以改。

### 5.3 界面

沙盒设置页（`SandboxSettingsPanel`）增加三档选择，放在现有状态和白名单上面。状态文案改成后端真名：Seatbelt、bubblewrap、MXC、Windows 旧沙盒、不可用。Windows 不可用时给安装按钮，按钮调用 helper 的 `setup`（见第 6 节）。文案同时进 `values/` 和 `values-en/`。

对话里新卡片，不复用 `PlanApprovalCard`。上面是命令或路径，下面两个动作：同意、拒绝。严格档的普通命令，按钮含义是「在沙盒里跑」。`sandbox=network` 和 `sandbox=off` 的按钮文案写明多出来的权限，避免用户以为点的仍是沙盒内执行。

### 5.4 模型怎么升级

`BashArgs` 增加 `sandbox`，取值 `default`、`network`、`off`，默认 `default`。工具描述写清三档下分别会发生什么。

沙盒拒绝的输出（非零退出、`Operation not permitted`、bwrap 网络错误）末尾加固定一句：若这次确实要出站，用 `sandbox=network` 再调一次；若必须写 `.git` 或沙盒外路径，用 `sandbox=off` 再调一次。两次都会请用户同意。宿主看到拒绝后不自行改参数重跑。

文件工具不增加这个参数。工作区外和 `.git` 由宿主分类后直接弹卡片。模型不需要先失败一次。

### 5.5 和子代理的关系

执行子代理会写文件、跑命令，研究子代理按现有工具裁剪本来就不能写、不能跑命令。执行子代理使用父会话的同一档位和同一个请求器：弹窗出现在父会话。研究子代理不挂执行同意。验证命令走 `runCommand`，因此自动档下工作区内的验证不弹，要网络的验证会弹。

## 6. 分平台怎么改

### 6.1 macOS

只改 `CommandSandbox` 的 profile 生成和 `wrap` 的分支。不换隔离技术。

`wrap` 按「档位 + 这一次的申请」选 profile：

- 全开，或这一次 `sandbox=off` 且已同意：不插入 `sandbox-exec`。perl 进程组前缀保留。
- 其他：`sandbox-exec -f profile`。profile 内容包含可写根、`.git` 拒绝、网络开关。缓存文件名的 hash 必须覆盖这些，否则改档位会复用旧 profile。

验收（本机，开发机就是 macOS）：

- 自动档写项目内文件成功。
- 写 `/tmp` 下新建文件成功。
- 写家目录任意非白名单文件 `Operation not permitted`。
- 写 `{项目}/.git/config` 失败。
- `curl https://example.com` 失败。
- 连 `127.0.0.1` 上由沙盒内自己拉起的端口成功。
- `sysctl-write` 仍在，`./gradlew` 能找到 JDK。
- 全开时上述出站和家目录写成功，且 `status.available=false`、后端显示为未套沙盒。

### 6.2 Linux

只改 `LinuxCommandSandbox.prepareMounts` 和 `status` 文案。

前缀在现有参数上调整：

- 可写 `--bind` 改为第 4.1 节的根。
- 每个存在的 `.git` 追加 `--ro-bind`。
- 默认 `--unshare-net`。`sandbox=network` 且已同意时不加。
- 探测命令使用和正式执行相同的前缀。现在已经是这样做的，网络开关会分出两份探测结果，各自缓存到该实例上。

不代装 bwrap。失败文本保留现在的安装提示（apt/dnf/pacman），并删掉提示词里的裸跑说法。

验收需要 Linux 或 `MEDERI_REQUIRE_LINUX_SANDBOX=1` 的现有测试入口。单测在任意宿主上断言 argv：含 `--unshare-net`、含 `--ro-bind` 的 `.git`、不含家目录缓存、`sandbox=network` 时没有 `--unshare-net`。真机再验写穿和出站。

### 6.3 Windows

JVM 进程是真实用户，做不到「以沙盒用户 `CreateProcessAsUser`」，也做不到直接进 MXC。Codex 因此把启动放进单独的 helper。Mederi 同样加一个只在 Windows 上构建的 helper，子命令三个：

**`probe`**

打印一行结构化结果：MXC 是否可用、旧沙盒是否已安装、不可用原因。MXC 可用性调用运行时探测（创建后立刻关掉一个空容器），不用 build 号推断。core 解析这行输出，填 `SandboxStatus`。helper 缺失或 probe 崩溃，视为两个后端都不可用。

**`setup`**

旧沙盒的一次性安装，触发 UAC。做这些事，少一件算安装失败：

- 创建两个本地用户，例如 `MederiSandboxOffline` 和 `MederiSandboxOnline`。口令随机，DPAPI 加密后存在沙盒用户读不到的位置。
- 防火墙规则：Offline 用户一切出站拒绝。Online 用户不套这组拒绝规则。
- 记录「安装完成」标记。设置页靠它决定能不能用旧后端。
- 不在安装时递归改写用户整个配置目录的 ACL。读权限放到 `run` 里按需处理，避免一次安装扫完整份用户目录。Codex 那次异步给 `C:\Users\<真实用户>`、`Windows`、`Program Files`、`ProgramData` 补读 ACE，是因为换了用户之后默认读不了别人的配置文件。helper 的 `run` 若发现读失败，返回明确错误，由设置页提供「补读权限」而不是每次命令都提权。

**`run`**

stdin 接收这一次的权限描述：可写根、只读的 `.git` 路径、要不要网络、要执行的 argv、cwd、超时由父进程管。helper：

1. 选用户：要网络用 Online，否则用 Offline。
2. 以该用户启动 runner，runner 再造 write-restricted token。限制 SID 列表里有一个只属于这次沙盒的 SID。
3. 可写根上给该 SID 写、执行、删除。`.git` 上给该 SID 拒绝写。真实用户原有的「自己可写整盘」不够，第二关会失败。
4. 把子进程的 stdout/stderr 接回父进程。退出码原样返回。
5. 父进程仍用 `ProcessRegistry` 记录 helper 的 pid。杀组时杀掉 helper，由 helper 带走上它拉起的子进程。做不到 posix 进程组时，helper 必须把子进程放进一个 Job Object，关掉 job 就整树退出。

选择顺序，每次 `wrap` 都走：

1. 全开或已同意的 `sandbox=off`：现在的 `cmd`/`bash.exe` 路径，不调用 helper。
2. `probe` 说 MXC 可用：走 MXC（下一步）。
3. 否则旧沙盒已安装：`helper run`。
4. 否则抛错，命令不启动。

**MXC**

Windows 11 上微软的 Execution Containers。helper 在 `probe` 成功后，`run` 可以把同一份权限描述交给 `BaseContainerRunner`，而不是走用户和 ACL。这条路径不修改宿主 ACL、不建用户、启动时不提权。网络策略由容器执行：回环允许，非回环默认拒绝；这一次要网络则打开出站。

MXC 探测失败或 `run` 失败：不退回裸跑，也不自动改走旧沙盒来掩盖 MXC 的错误。选择在 `probe` 时定下来。已经选了 MXC 而 `run` 失败，就把失败返回给模型。下一 turn 可以重新 probe。这和 Codex「命令失败不触发后端回退」一致。

在 helper 写完之前，第 4 步提前生效：Windows 上严格和自动直接拒绝 `bash`，文案说明命令沙盒还没装好。文件工具的档位判断可以先于 helper 落地，因为它们不需要 OS 后端。

不把 WSL2 当作 Windows 方案。Mederi 要跑的是 `cmd`、PowerShell、`gradlew.bat`。WSL 互操作开着时，Windows 程序会逃出 Linux 命名空间。

## 8. 落地顺序

每一步都能单独编译、单独验，不把 Windows helper 堵在 macOS 行为前面。

**第一步：档位和同意，三端文件工具先统一。** 策略类型、偏好、设置页三档、请求器、事件、四处契约、对话卡片。`write_file`、`edit_file`、`apply_patch`、`office_write` 改用同一判断。Windows 和尚未改 profile 的 macOS/Linux 上，命令侧先接上「该问就问」；Windows 严格/自动在 helper 出现前直接拒绝命令。单测覆盖第 3 节的矩阵，不启动沙盒。

**第二步：macOS 和 Linux 的封套。** 收可写根、`.git` 只读、网络默认关、`sandbox=network` 只开网络。本机按第 6.1 节的清单跑。Linux 先锁 argv 单测。

**第三步：`web_search` / `web_fetch` 离开 `curl`。** 自动档下一条不带网络的 `bash` 出不了站，这两个工具仍返回搜索结果。

**第四步：Windows 旧沙盒 helper。** `probe`、`setup`、`run`、Job Object、设置页安装。验收：工作区可写、工作区外不可写、`.git` 不可写、Offline 用户出站失败、Online 用户出站成功、helper 崩溃时父进程不改为裸跑。

**第五步：MXC。** `probe` 可用才走。失败不回退。没有 MXC 的机器停在第四步。

## 9. 这次不做

- 把读收成「只能读工作区」，或默认拒绝 `~/.ssh`、`~/.aws`。Codex 日常档也是读全盘。
- 域名允许列表和本地出站代理。网络只有「关」和「这一条命令出站全开」。
- 用另一个模型代替用户点同意。
- 把三档塞进 `AgentMode`。计划批准者仍然是 APPROVAL / AUTONOMOUS。
- 记住命令或路径，让下一次不再问。长期放行只走设置页额外路径。
- 用 `HTTPS_PROXY` 冒充网络沙盒。
- 用 WSL2 代替 Windows 原生后端。
- 代装 bwrap，或在探测失败时改宿主的 AppArmor。
