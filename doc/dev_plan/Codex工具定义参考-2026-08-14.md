# Codex 工具定义参考（写法搜集）

> 创建日期：2026-08-14
> 来源：Codex 源码 `codex-main/codex-rs/core/src/tools/handlers/*_spec.rs` 及内联 spec。
> 用途：作为 Mederi 用 Koog `Tool`/`SimpleTool` 写工具时的**提示词与参数写法参考**——工具 description 和参数 description 怎么写、required 怎么标、输出怎么设计，全部抄 Codex 的成熟做法。

## 〇、Codex 工具 spec 与 Koog 的对应关系

Codex 用 `ResponsesApiTool { name, description, strict, defer_loading, parameters, output_schema }` + `JsonSchema::string/number/boolean/array/object(desc)` 描述工具。对应到 Koog：

| Codex | Koog | 说明 |
|---|---|---|
| `JsonSchema::string(Some("..."))` | `@LLMDescription("...")` + `ToolParameterType.String` | 参数说明直接搬 |
| `parameters.required = [...]` | `requiredParameters`（字段**无默认值**即进 required） | Koog 自动推断：有默认值→optional |
| `output_schema` | 无对应 API → 用 `encodeResultToString` 定制结果文本 | Koog 靠结果文本，无显式 output schema |
| `defer_loading` | 无直接对应 | Koog 工具总是随 agent 全量暴露 |
| `ToolSpec::Namespace`（如 `clock.*`） | 无命名空间 → 工具名加前缀（如 `clock.curr_time`） | Koog 无 namespace，用带点工具名模拟 |
| `ToolSpec::Freeform`（apply_patch） | 无对应 → 需扩展 Tool 支持 raw 文本参数 | apply_patch 特例 |

Codex 工具名常量大写常量、snake_case；描述风格统一为「做什么 + 什么时候用 + 注意事项」。

## 一、核心能力工具（对应工具补全计划）

### 1. update_plan（计划管理）

- 名称：`update_plan`
- description：
  ```
  Updates the task plan.
  Provide an optional explanation and a list of plan items, each with a step and status.
  At most one step can be in_progress at a time.
  ```
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `plan` | array&lt;object&gt; | ✅ | 计划步骤列表（整体替换） |
  | ↳ `step` | string | ✅ | 步骤文本 |
  | ↳ `status` | string enum | ✅ | `pending` / `in_progress` / `completed` |
  | `explanation` | string | ❌ | 对本次计划更新的可选解释 |
- 输出：固定文本 `"Plan updated"`。
- 备注：schema 写「至多一个 in_progress」但 handler 不强制校验（靠模型自觉）。

### 2. get_context_remaining（上下文余量）

- 名称：`get_context_remaining`
- description：`"Get the remaining tokens in the current context window."`
- 参数：无
- 输出 schema：`{ "tokens_left": integer | null }`
- 输出文本：`"You have {n} tokens left in this context window."`（null 时 unknown）

### 3. new_context_window → 实际工具名 `new_context`

- 名称：`new_context`
- description：`"Start a new context window. Does not clear, reset, or otherwise affect environment state."`
- 参数：无；输出：无。

### 4. current_time → 实际工具名 `clock.curr_time`

- 名称：`clock.curr_time`（命名空间 `clock`，描述 `"Tools for reading and waiting on time."`）
- 工具 description：`"Return the current time in UTC."`
- 参数：无
- 输出 schema：`{ "current_time": "YYYY-MM-DD HH:MM:SS UTC" }`
- 输出文本：`"It is {formatted_time}."`

### 5. sleep → 实际工具名 `clock.sleep`

- 名称：`clock.sleep`（同 `clock` 命名空间）
- 工具 description：
  ```
  Pause execution for a specified duration. The sleep ends early when new input arrives for the active turn. Returns the elapsed wall-clock time.
  ```
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `duration_ms` | number | ✅ | `How long to sleep in milliseconds. Must be between 1 and 43200000.` |
- 输出文本：`"Wall time: {n} seconds\nSleep completed."` / `"Sleep interrupted by new input."`
- 备注：`exposure = DirectModelOnly`（不对用户暴露）。

### 6. wait_for_environment（等待环境就绪）

- 名称：`wait_for_environment`
- 默认 description：
  ```
  Wait for a selected execution environment marked as `starting` to become available. Use this when the current task needs that environment's files, commands, or installed capabilities. Do not wait if the task can be completed using tools already available, such as connectors. Waiting may take several minutes and blocks other tool calls. If startup fails, continue without that environment.
  ```
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `environment_id` | string | ✅ | `The exact environment ID marked as starting in <environment_context>.` |
- 输出：`{ "environment_id": "...", "status": "ready" }`。

### 7. tool_search（延迟工具搜索）

- 名称：`tool_search`
- description（动态生成，含来源清单）：
  ```
  # Tool discovery
  Searches over deferred tool metadata with BM25 and exposes matching tools for the next model call.
  You have access to tools from the following sources:
  - Google Drive: ...
  Some of the tools may not have been provided to you upfront, and you should use this tool (`tool_search`) to search for the required tools. For MCP tool discovery, always use `tool_search` instead of `list_mcp_resources` or `list_mcp_resource_templates`.
  ```
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `query` | string | ✅ | `Search query for deferred tools.` |
  | `limit` | number | ❌ | `Maximum number of tools to return. Defaults to 8.` |
- 备注：`ToolSpec::ToolSearch { execution: "client" }`，返回可加载工具 spec。

### 8. view_image（查看图片）

- 名称：`view_image`
- description：
  ```
  View a local image file from the filesystem when visual inspection is needed. Use this for images already available on disk.
  ```
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `path` | string | ✅ | `Local filesystem path to an image file.` |
  | `detail` | string enum | ❌ | `high` / `original`；`Image detail level. Defaults to high; use original to preserve exact resolution.`（按能力可选暴露） |
  | `environment_id` | string | ❌ | `Environment id from <environment_context>. Omit to use the primary environment.` |
- 输出：`{ "image_url": dataURL, "detail": "high"|"original" }`。

### 9. exec_command（统一执行命令）

- 名称：`exec_command`
- description：`"Runs a command in a PTY, returning output or a session ID for ongoing interaction."`
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `cmd` | string | ✅ | `Shell command to execute.` |
  | `workdir` | string | ❌ | `Working directory for the command. Defaults to the turn cwd.` |
  | `tty` | boolean | ❌ | `True allocates a PTY for the command; false or omitted uses plain pipes.` |
  | `yield_time_ms` | number | ❌ | `Wait before yielding output. Defaults to 10000 ms; effective range is 250-30000 ms.` |
  | `max_output_tokens` | number | ❌ | `Output token budget. Defaults to 10000 tokens; larger requests may be capped by policy.` |
  | `shell` | string | ❌ | `Shell binary to launch. Defaults to the user's default shell.` |
  | `login` | boolean | ❌ | `True runs the shell with -l/-i semantics; false disables them. Defaults to true.` |
  | `environment_id` | string | ❌ | 多环境时可选 |
  | `sandbox_permissions` / `justification` | … | ❌ | 权限审批参数 |
- 输出 schema：`{ chunk_id, wall_time_seconds, exit_code, session_id, original_token_count, output }`（`required: [wall_time_seconds, output]`）。

### 10. write_stdin（向运行中会话写输入）

- 名称：`write_stdin`
- description：`"Writes characters to an existing unified exec session and returns recent output."`
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `session_id` | number | ✅ | `Identifier of the running unified exec session.` |
  | `chars` | string | ❌ | `Bytes to write to stdin. Defaults to empty, which polls without writing.` |
  | `yield_time_ms` | number | ❌ | `Wait before yielding output. Non-empty writes default to 250 ms and cap at 30000 ms; empty polls wait 5000-300000 ms by default.` |
  | `max_output_tokens` | number | ❌ | `Output token budget. Defaults to 10000 tokens; larger requests may be capped by policy.` |
- 输出 schema：同 exec_command（`unified_exec_output_schema`）。

### 11. apply_patch（多文件补丁，FREEFORM）

- 名称：`apply_patch`
- description：`"The apply_patch tool can be used to edit files. This is a FREEFORM tool, so do not wrap the patch in JSON."`
- 形态：`ToolSpec::Freeform`，参数是 Lark grammar 定义的补丁文本（`*** Begin Patch` … `*** End Patch`），不是 JSON。
- 详见 [apply_patch 开发文档](tools/apply_patch.md)。

## 二、多 Agent 协作工具（Koog 有 subgraph，仅作写法参考）

全部 snake_case、`strict:false`、`defer_loading:None`。命名空间 `multi_agent_v1`（描述 `"Tools for spawning and managing sub-agents."`）内为 v1 工具；v2 为裸 function。

### 12. spawn_agent（启动子 agent）

- description（v1 精简版，实际带大量「何时委托 vs 自己做」长文）：
  ```
  Spawn a sub-agent for a well-scoped task. Returns the spawned agent id plus the user-facing nickname when available. Spawned agents inherit your current model by default. Omit `model` to use that preferred default; set `model` only when an explicit override is needed.
  ```
- 参数（v1）：`message`/`items`（任务）、`agent_type`、`fork_context`（bool：是否 fork 历史）、`model`、`reasoning_effort`、`service_tier`。
- 参数（v2）：`task_name`（✅，`Use lowercase letters, digits, and underscores.`）、`message`（✅）、`agent_type`、`fork_turns`（`Defaults to all. Use none, all, or a positive integer string such as 3.`）、`model`、`reasoning_effort`、`service_tier`。
- 输出 schema（v2）：`{ task_name, nickname }`。
- 备注：v2 的 description 是超长引导文（何时委派、如何设计子任务、委派后怎么做），展示了「description 里写完整使用策略」的做法——**这是 Codex 工具提示词的精华**。

### 13. send_message（v2，发消息不触发回合）

- description：`"Send a message to an existing agent. The message will be delivered promptly. Does not trigger a new turn."`
- 参数：`target`（✅）、`message`（✅，加密字段）。

### 14. followup_task（v2，追加任务触发回合）

- description：
  ```
  Send a follow-up task to an existing non-root target agent and trigger a turn if it is idle. If the target is already running, deliver the task promptly at message boundaries while sampling, or after the pending tool call completes.
  ```
- 参数：`target`（✅）、`message`（✅）。

### 15. wait_agent（等待子 agent）

- description（v2）：
  ```
  Wait for a mailbox update from any live agent, including queued messages and final-status notifications. The wait also ends early when new user input is steered into the active turn. Does not return the content; returns either a summary of which agents have updates (if any), an interruption summary for steered input, or a timeout summary if no activity arrives before the deadline.
  ```
- 参数：`timeout_ms`（❌，`Defaults to {default}, min {min}, max {max}.`）。
- 输出（v2）：`{ message, timed_out }`。

### 16. interrupt_agent（中断子 agent）

- description：`"Interrupt an agent's current turn, if any, and return its previous status. The agent remains available for messages and follow-up tasks."`
- 参数：`target`（✅）。
- 输出：`{ previous_status }`。

### 17. list_agents（列出子 agent）

- description：`"List live agents in the current root thread tree. Optionally filter by task-path prefix."`
- 参数：`path_prefix`（❌）。
- 输出：`{ agents: [{ agent_name, agent_status }] }`。

### 18. close_agent（关闭子 agent）

- description：
  ```
  Close an agent and any open descendants when they are no longer needed, and return the target agent's previous status before shutdown was requested. Completed agents remain open and count toward the concurrency limit until closed. Don't keep agents open for too long if they are not needed anymore.
  ```
- 参数：`target`（✅）；输出：`{ previous_status }`。

## 三、用户交互工具

### 19. request_user_input（向用户提问）

- description（按可用模式生成）：
  ```
  Request user input for one to three short questions and wait for the response. This tool is only available in {allowed_modes}.
  ```
- 参数：
  | 参数 | 类型 | required | description |
  |---|---|---|---|
  | `questions` | array&lt;object&gt; | ✅ | `Questions to show the user. Prefer 1 and do not exceed 3` |
  | ↳ `id` | string | ✅ | `Stable identifier for mapping answers (snake_case).` |
  | ↳ `header` | string | ✅ | `Short header label shown in the UI (12 or fewer chars).` |
  | ↳ `question` | string | ✅ | `Single-sentence prompt shown to the user.` |
  | ↳ `options` | array&lt;object&gt; | ✅ | `Provide 2-3 mutually exclusive choices. Put the recommended option first and suffix its label with "(Recommended)". Do not include an "Other" option in this list; the client will add a free-form "Other" option automatically.` |
  | ↳↳ `label` | string | ✅ | `User-facing label (1-5 words).` |
  | ↳↳ `description` | string | ✅ | `One short sentence explaining impact/tradeoff if selected.` |

## 六、Codex 写工具提示词的风格提炼（写 Koog 工具时照抄）

1. **description = 一句话说清「做什么 + 什么时候用」**，必要时分句补「别什么时候用」（如 wait_for_environment 的 `Do not wait if...`、spawn_agent 的委派准则）。
2. **每个参数都有 description**，且说清**取值规则/默认值/边界**，如 `Defaults to 10000 ms; effective range is 250-30000 ms`、`Must be between 1 and 43200000`、`Omit to use the primary environment`。
3. **required 只标真正必填**（`Some(vec!["cmd"])`），其余 optional——Koog 端对应「字段无默认值=required」。
4. **输出也写 schema**：复杂输出（多 agent、exec）声明 `output_schema` 让模型预期返回结构；简单输出用一句话文本。
5. **工具名 snake_case**；命名空间用点前缀模拟（`clock.curr_time`）。
6. **复杂使用策略写进 description**（spawn_agent 长文），这是 Codex 引导模型正确用工具的关键手段；Mederi 可把这类策略放进 `ToolDescriptor.description` 或 systemPrompt。
7. **错误信息是给模型看的**：校验失败返回 `RespondToModel` 带原因，模型据此自我纠正。
