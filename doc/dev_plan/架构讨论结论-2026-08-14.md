# Mederi 架构讨论结论

> 日期：2026-08-14
> 状态：已确认，待实施
> 背景：补全 Koog 工具前，先纠正 Mederi 基础架构和领域模型。

---

## 一、核心概念纠正

### 1. Agent 不是运行时实体，只是一套配置

Agent 本质上就是：
1. 用哪个模型
2. 参数是什么（thinking level 等）
3. system prompt 是什么
4. 可用工具有哪些

Agent **无状态**，只有配置。运行时是 Koog 的 `AIAgent`，由 Mederi 按需创建和销毁。

### 2. Session 是对话容器，不持有 Agent

之前 `Session.agentId` 是错误设计。Session 应该直接持有配置快照：
- `modelId`
- `systemPrompt`
- `tools`
- `thinkingLevel`
- `mode`（PLAN/BUILD，默认模式）
- 对话历史
- 运行时微量状态（plan、`new_context_window` 标志等）

Session 不引用 Agent，创建 Session 时可以从 Agent 预设拷贝配置，但之后独立。

### 3. 每次发消息创建一个 AIAgent，跑完销毁

```text
sendMessage
  → 加载 Session 历史
  → 根据 Session 配置 + 本次请求覆盖参数 创建 Koog AIAgent
  → agent.run(input, sessionId) 并监听 EventHandler 流式帧
  → API 返回 / 调工具 / done
  → ChatMemory 把对话记录存回 Session 历史
  → 销毁 AIAgent
```

这是正确且足够简单的生命周期。不需要长期持有 AIAgent，不需要对象池/工厂。
流式输出通过 EventHandler 拦截 TextDelta / ReasoningDelta，转成 MESSAGE_DELTA 事件。

### 4. AgentMode 是权限，不是不同 Agent

- `PLAN`：只读，禁止写、删
- `BUILD`：读写

Mode 差异通过**工具权限过滤**实现，不需要不同的 agent runtime 或 system prompt。

---

## 二、确定的最简架构

```text
Mederi
├── Agent（配置预设：名字 + model + systemPrompt + tools + thinkingLevel + defaultMode）
├── Session（id + title + 配置快照 + 历史 + plan 等微量状态）
├── TurnExecutor（每次 send 创建 AIAgent，跑完销毁）
├── ToolRegistryFactory（按 mode 过滤工具）
└── HistoryStore（历史持久化）
```

### 关键设计点

| 组件 | 职责 | 生命周期 |
|---|---|---|
| Agent | 可复用配置预设 | 持久 |
| Session | 对话容器 + 配置快照（含 mode 默认） | 持久 |
| Koog AIAgent | 执行一次 turn | 每次 send 创建并销毁 |
| ToolRegistry | 本次 turn 可用工具 | 每次 send 创建 |
| SendMessageRequest | 可覆盖 mode/modelId/thinkingLevel | 单次请求 |

---

## 三、设计哲学

- **尽可能简单**：不要 SessionRuntime、不要 Agent 工厂池、不要长期持有运行时
- **尽可能代码少**：Mode 只用权限过滤实现
- **尽可能提示词少**：system prompt 极简，工具用法写在 tool description 里

---

## 四、工具补全路径（按此架构）

1. 重构领域模型
   - `Session` 去掉 `agentId`，直接存配置快照
   - `Agent` 改为纯配置预设
   - `AgentRunner` 改为 `TurnExecutor`

2. 实现 `ToolRegistryFactory`
   - 所有工具注册
   - 按 `AgentMode` 过滤

3. 补工具
   - 第一优先级：`update_plan`、`get_context_remaining`、`new_context_window`
   - 后续：`apply_patch`、`current_time` 等

---

## 五、已明确的点

- `AgentMode` 放在 Session 里作为默认，SendMessageRequest 可以每次覆盖。
- `update_plan` 等工具的 session 状态存在 Session 里（plan / new_context_window 字段）。
- 是否支持运行中 abort / 追加消息：已实现 abort；追加消息可在未来 job 合并机制中扩展。
