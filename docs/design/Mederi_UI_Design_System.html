Mederi UI 设计规范

从"能用"到"高级"：一套可执行的说明

这份文档把"不够高级"拆成可判断、可实现的具体规则，覆盖整体配色、排版间距、右侧概览面板与主对话流三处，末尾附 Compose 取值速查，可以直接交给实现的同学或 agent。

1"不够高级"具体是什么

这种感觉通常不是审美问题，而是四个结构性问题叠加的结果：

强调色太多
橙(待批准)、蓝(状态点/链接)、绿(在线)、紫(选中)同时出现，注意力被分散，感觉杂乱。
靠边框分区，不靠留白
用细线分割每一块，而不是用背景层次+间距；边框越多越像表格/终端，不像产品。
信息层级扁平
标签、数值、正文几乎同字号同灰度，眼睛需要主动"找"重点，而不是被引导到重点。
等宽字体滥用
模型名、工具名这类普通标签也套用等宽字体+灰底 pill，整体偏"开发者控制台"而非"产品"。

2整体配色

规则很简单：只保留一个品牌强调色，其余颜色全部收作"语义色"——只在对应状态下才出现，不参与日常界面装饰。

品牌强调色
选中态 / 主按钮 / 链接
成功 / 在线
仅状态点、完成态
待处理
仅"待批准"类徽标
错误 / 危险
仅报错、删除确认
层级用途说明
surface-0页面底色整个应用背景，最暗（深色下）
surface-1卡片背景消息卡、面板卡片主用色，比页面亮一档
surface-2弹出层/嵌套区块代码输出块、弹窗，再亮一档，用于"层次"而非边框

当前截图接近这个结构，但边框太密、强调色太杂；把"分割线"预算砍掉一半，换成 surface 层次和间距。

3排版与间距

用途字号/字重颜色
关键数值(费用/百分比)22–24sp / 500text-primary
正文/卡片标题14–15sp / 500text-primary
次要信息/标签12–13sp / 400text-secondary
辅助提示/时间戳11–12sp / 400text-muted
  • 停用全大写分区标题（如 RUNTIME、EXTENSIONS）— 改成中文/句首大写的小号弱化标签，全大写是最快让界面显"工具感"而非"产品感"的因素之一。
  • 区块间距最少 24dp，卡片内边距 16–20dp，卡片之间不再画分割线，靠间距区分。
  • 圆角统一：卡片 14dp，按钮/输入控件/徽标 8dp，不再用"只画左边框"的强调方式（如当前橙色左边条的 Plan 卡）。

4右侧概览面板

对应此前给出的可视化稿，落成具体规则：

  • 数字卡片化：费用、Token 用量做成 2 列数字卡片（surface-1，圆角 8dp），大号数值 + 小号说明文字，替代当前逐行的 label/value 排布。
  • Plan 步骤用状态图形：已完成 = 勾选图标（success 色）、进行中 = 实心圆点（accent 色）+ 加粗、待处理 = 空心/浅色圆点，不再用整行同色文字区分状态。
  • Extensions 合并为一张卡片：Subagent / MCP Tools / Skill 三行放进同一张卡片内，行与行之间用极浅的 1px 内部分割线，不再是三个独立小节。
  • 原始消息流默认折叠：只保留一行"共 N 条 ›"的入口，点击展开，不再默认铺开占用侧栏三分之一高度。

5主对话流

当前问题是三类内容（叙述文字、终端输出、决策卡片）视觉上没有区分开，混在一起阅读很累。建议明确分成三种卡片类型：

叙述文本
assistant 的说明性文字，不加卡片、不加边框，就是普通段落，保持阅读速度。
工作过程卡（可折叠）
思考过程/命令/文件读取整体收进一张 surface-1 卡片；命令与终端输出单独用 surface-2 的"代码块"包裹，等宽字体只出现在这个子区域内，不要泄漏到卡片标题或过渡语上。
决策 / 审批卡
问答、Plan 审批、Diff 摘要统一用同一种卡片外观（完整边框 + 14dp 圆角），只用一个强调色的按钮做主操作，不再用左侧色条区分类型——类型用卡片顶部一个小徽标文字代替（如"问题 1/1""计划待批准"）。
