# 供应商设置：可扩展的管理与添加布局

> 2026-10-29：用户指出内置供应商增多后选取困难。布局方案已获用户批准，S2a目录/管理与对齐代码及组件验证完成，见[交付记录](settings-provider-catalog-delivery.md)；S2b详情/模型/表单代码与组件验证完成，见[交付记录](settings-provider-details-delivery.md)，完整APP仍待验。
> 上级：[设置总计划](settings-redesign-plan.md)。沿用同一canonical设计规格、MVVM与共享组件。

## 1. 从实际代码确认的问题

目标代码：`ui/settings/ProviderSettingsPanel.kt`、`BuiltinPresetsSection.kt`、`ProviderSettingsViewModel.kt`、`ProviderDetailWorkspace.kt`、`CustomProviderForm.kt`。

1. 桌面216dp供应商栏把“添加按钮→已配置列表→全部未添加预设”排在同一滚动区；窄屏同样把两种列表串接。预设越多，列表越长，找已有配置和发现新预设互相干扰。使用Column.forEach会组合全部行，缺少大目录的惰性列表。
2. “添加供应商”实际直接`startCreateCustomProvider()`；内置只能去下方“推荐预设”逐个翻。标签表达与真实入口不一致，内置并非优选推荐列表而是所有未添加预设。
3. 当前只有模型搜索`uiState.searchQuery`/`filteredModels`，没有已配置供应商和预设目录搜索。新搜索不得复用模型查询。
4. 内置目录契约只有`builtinPresets: List<String>`，没有地域、官方热度、价格/能力、别名等元数据。不能画出看似丰富而缺乏真理源的筛选器/推荐排名。
5. `BuiltinPresetsSection`用所有已配置name（含自定义）忽略大小写排除预设。显示名相同不一定是同一个内置来源；未来新增目录必须避免把自定义同名项当成已配置内置。现有契约可用isBuiltin+真实预设名做有限匹配；无法确定的项不伪标身份，不在UI维护手工映射表。
6. AddBuiltinProviderDialog提交后立即关闭；VM已有isSavingCredentials与onComplete(Result<ProviderConfig>)，失败反馈却在详情区呈现。新布局要让错误留在实际操作位置，复用结果回调与已有状态，不自行伪造添加成功。
7. 新设置左侧分类已占184dp，供应商内部再216dp侧栏+详情，会形成三列。必须根据供应商实际剩余宽度切换布局，不能只按整个窗口宽判断“桌面”。

## 2. 推荐方案：管理常驻，添加按需进入目录

### A. 日常管理

```text
设置分类       供应商管理                         ＋ 添加供应商
               已配置供应商 [查找名称或端点…]
               ┌─────────────────┬────────────────────────┐
               │ OpenAI          │ 当前供应商身份/原操作   │
               │ 私有服务         │ Key管理、同步、模型列表 │
               │ OpenRouter      │ 模型搜索和能力过滤      │
               └─────────────────┴────────────────────────┘
```

- 主供应商列表只呈现真实已配置项，包含已添加内置与自定义；不再常驻全部预设。
- 固定添加入口与搜索，不随长列表滚走；列表惰性加载，以provider.id为key，保留选中/阅读位置。
- 已配置项搜索真实name和baseUrl，不搜索明文/掩码Key。名称为主、端点可作次级辨认同名服务；状态只说有依据的“已配置/未配置”，有Key不冒充网络连通验证成功。
- 搜索只改变展示投影，不自动切换当前选中或修改模型查询；删除/更新仍读VM真实状态。无匹配提供清除查询，不等同“没有任何供应商”。
- 已配置项为零时，内容中心给“添加供应商”入口和简短说明，无空壳详情，不强制用户理解自定义/内置术语。
- 常规宽度保持管理列表+详情；剩余宽不足（或字体放大）改列表→详情单列下钻，有返回；七类设置导航不再额外加一套Provider顶层Tab。

### B. 添加目录（替换供应商工作区，不堆第三个侧栏或多层弹窗）

```text
设置分类       ‹ 返回供应商管理       添加供应商
               [ 搜索内置供应商名称…                 ]
               使用自定义端点                          创建连接 ›

               内置预设（匹配数量）
               名称A                         选择 ›
               名称B                         已配置 · 管理 ›
               名称C                         选择 ›
               …（独立滚动、搜索栏固定）
```

- 点击“添加供应商”进入同一内容区域的完整目录；默认直接呈现全部内置，而不是再点一个“内置”Tab。自定义连接作为固定且同等可发现的入口，避免藏在无结果页尾部。
- 目录以轻量列表行为主，ProviderIcon+全名+必要状态+明确动作；不画大量大Logo卡或重复说明。宽区确有空间时可以用同一行组件排两列，但首版优先单一惰性列表，按约50/100/300条验收，避免为两种列表维护不同实现。
- 先做名字大小写无关的查询与稳定字母序（比较规则一致，不依赖每次重组原始顺序）；不宣称支持拼音/中文别名/地区/热度。若需要这些能力，先建立真实目录元数据，再作为独立功能规划。
- 已配置内置仍可在目录中找到，以“已配置·管理”回到对应providerId，而不是从目录消失。匹配必须带内置来源事实；若将来有多个同名配置，进入匹配的管理列表由用户选，不随机跳到第一个。
- 无结果明确显示查询无匹配，保留自定义入口与清除搜索；空目录也不假装网络加载，当前builtinPresets为现有静态契约属性。
- 点击未添加预设进入同区域凭据步骤：返回目录、明确预设身份、沿用原API Key/预设参数说明，使用共同字段/按钮/错误View。不同时弹“目录Dialog→凭据Dialog”。
- 切入凭据后返回目录，保留目录搜索与滚动。取消添加不改变已有配置/模型选择；离开设置清理敏感草稿，不写进设备偏好。
- 添加中使用isSavingCredentials禁用重复提交；失败保留当前草稿并显示真实错误。只有onComplete成功才返回管理、由VM选中新providerId并沿原链路自动同步模型。空Key仍禁用、原trim行为保留，不改变Core API。
- 自定义连接复用现有字段与创建链路，返回入口明确；名字/BaseURL/Key/协议/推理等原能力保留。本轮不重定义预设数据或开放原来不可编辑的字段。

## 3. 搜索、状态与复用边界

### 三种搜索独立

| 搜索 | 输入作用域 | 数据 | 不应触及 |
|---|---|---|---|
| 已配置供应商 | 当前管理列表 | ProviderItemUiState.name/baseUrl | 当前模型query、目录query、供应商配置 |
| 内置目录 | 添加流程 | builtinPresets真实名称 | 已配置管理query、模型query |
| 模型 | 当前供应商详情 | 原filteredModels | 目录与供应商导航 |

新增展示投影与添加流程归ProviderSettingsViewModel，Content只接数据与回调。扩展既有ProviderSettingsUiState而非建立第二份providers列表；添加流程使用明确的页面/步骤状态，不堆catalogOpen/dialogOpen/isCreatingCustom等互相冲突的布尔。旧isCreatingCustom若过渡保留应派生/单向适配，不成为双重真理源。只管理展现步骤，领域创建仍由既有AiCore完成。

共享内容原子计划：已配置行、目录预设行、搜索字段、空态、返回动作、共同错误/保存反馈；宽窄只换容器，不复制两套点击/禁用逻辑。使用现有MederiDialog/ConfirmDialog/WorkspaceActionButton/Menu/Tooltip；目录是可搜索工作区，不能滥用普通下拉菜单当300项目录。凭据步骤不自行绘制另一套确认弹窗。

预设身份边界必须如实记录：当前契约只有名称，无稳定presetId。第一版在内置来源+原名范围匹配；无法证明对应关系的情况不标“已添加”。若实际业务需要支持预设重命名、同预设多实例或别名，则需后续契约四处同步补来源ID，不能在UI字符串手术推断。本批不静默改变Core创建/去重规则。

## 4. S2拆成两个可验收批次

### S2a 管理列表与添加流程（先做）

- 改ProviderSettingsPanel/BuiltinPresetsSection与VM的表现状态；提取可测纯Content/投影。
- 管理侧仅已配置，新增两个独立查询，惰性列表与精确选中，目录/凭据/自定义步骤。
- 详情仍调用原ProviderDetailWorkspace/原模型过滤，先解决规模与选取问题，不同时大改所有模型控件。
- 新增中英搜索/目录/错误状态文案，复用共同原子，不新增依赖。

行为验收：已有配置0/1/30项；预设10/100/300项；大小写/空格/无结果；配置同名自定义不被误标为内置；目录已配置项精确跳转；取消/返回保留展示状态；重复提交禁用；失败不丢草稿且可再提交；成功才关闭流程并选新ID；三种搜索彼此独立；真实模型过滤回归；窄宽与150/200%字体动作可达；长列表键盘/滚动。

### S2b 详情、模型与Provider表单（随后）

- 在S2a新工作区里收敛ProviderDetailWorkspace/ModelRow/Key与Model Dialog/CustomForm及ProviderTokens。
- 供应商身份/端点/Key操作轻量分层，模型工具栏去重复层级；模型搜索/能力/批量/刷新/手动添加/元数据权限完整保留。
- 跟随总设置S2功能验收，不在目录改造时顺带改模型数据、协议或请求链路。

每批实施前补精确spec/验证命令，结束以实际Compose测试、wasm编译、深浅/窄宽预览登记；没有APP实机环境则明确未验。S2a实际结果登记于settings-provider-catalog-delivery.md，此文保留设计依据，不把S2a结果扩展为S2b完成。

## 当前决定

采用“已配置管理常驻＋添加时打开完整搜索目录”的方向。先S2a解决列表规模，再S2b统一详情与表单。暂不增加收藏、最近使用、热门推荐、国家/价格/协议筛选等缺少当前数据或非必要的机制。以可理解、可扩展和同一套View为准，不用更多折叠层掩盖长列表。
